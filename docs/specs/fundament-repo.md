# Fundament repo

- **Status:** Aktualny (2026-11-15) · **Historia:** M1, M2, M7 · **ADR-y:** [0011](../adr/0011-warstwy-aplikacji.md), [0012](../adr/0012-web-domeny-i-ui.md)

## Cel

Monorepo, w którym wygodnie i bezpiecznie dodaje się funkcje: wspólny TypeScript, lint, testy, granice warstw i CI pilnujące jakości każdej zmiany.

## Wymagania

| #   | Wymaganie                                                                                                                                                          |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| R1  | Yarn 4 workspaces: `apps/web`, `apps/server`, `packages/game-core`, `packages/protocol`.                                                                           |
| R2  | Wspólny TypeScript w trybie strict; `yarn typecheck` sprawdza wszystkie pakiety.                                                                                   |
| R3  | ESLint (z granicami warstw z ADR-0011 i ADR-0012) i Prettier; `yarn lint` i `yarn format:check` sprawdzają całe repo; hook `pre-commit` poprawia pliki w commicie. |
| R4  | Vitest we wszystkich pakietach; `yarn test` uruchamia wszystko, `yarn test:coverage` raportuje pokrycie.                                                           |
| R5  | CI (GitHub Actions) dla każdego PR i pushu na `main`; czerwone CI blokuje merge.                                                                                   |

## Scenariusze akceptacyjne

| #   | Given                                                            | When                          | Then                                                               |
| --- | ---------------------------------------------------------------- | ----------------------------- | ------------------------------------------------------------------ |
| S1  | Świeży klon, Node z `.nvmrc`                                     | `yarn install && yarn test`   | Instalacja bez zmian w `yarn.lock`, testy przechodzą               |
| S2  | `web` i `server` importują `@tetris/game-core`                   | `yarn typecheck && yarn test` | Import działa bez budowania `game-core`                            |
| S3  | Błąd typów, lintu, formatowania lub import przez granicę warstwy | Odpowiednia komenda           | Kod wyjścia ≠ 0 i wskazany plik                                    |
| S4  | PR do `main`                                                     | CI się kończy                 | Install, lint, format, typecheck i test widoczne jako osobne kroki |
| S5  | PR z nieprzechodzącym testem                                     | CI się kończy                 | Status czerwony, merge zablokowany przez ruleset                   |

## Design

```
.github/workflows/ci.yml   .yarnrc.yml (node-modules, yarnPath)   .nvmrc (26)
package.json               tsconfig.base.json   eslint.config.js   vitest.config.ts
apps/web            @tetris/web        Vite + React; app/ domains/ board/ hooks/ ui/ core/
apps/server         @tetris/server     Express + ws; game/ rooms/ accounts/ db/ play/ ws/ http/ observability/
packages/game-core  @tetris/game-core  czysty TS (silnik gry)
packages/protocol   @tetris/protocol   typy i walidacja wiadomości
```

| Obszar            | Decyzja                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Menedżer pakietów | Yarn 4 przypięty w repo (`yarnPath`), `nodeLinker: node-modules` dla zgodności z Vite i ESLintem; Node 26 nie ma Corepacka                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| Pakiety           | `@tetris/*`, `private: true`, zależności przez `workspace:*`; pakiety wewnętrzne bez builda (`exports` → `src/index.ts`), do obrazu trafiają przez esbuild                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| TS                | TypeScript 6.0 (typescript-eslint nie obsługuje jeszcze 7.x), `strict`, `noUncheckedIndexedAccess`, `moduleResolution: "bundler"`, `noEmit`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| Lint              | ESLint 10 flat config + `typescript-eslint` (type-checked) + `eslint-config-prettier`; reguła `boundaries` pilnuje kierunku importów między katalogami (ADR-0011, ADR-0012). Styl: tylko funkcje strzałkowe (`func-style: expression`, `prefer-arrow-callback`, zakaz `function` poza metodami) i klamry przy każdym `if`/pętli (`curly: all`). Prettier: bez średników, apostrofy, szerokość 100                                                                                                                                                                                                                                                                                                                                              |
| Hook              | husky `pre-commit` → lint-staged: `prettier --write` i `eslint --fix`; CI pozostaje bramką                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| Testy             | Root `vitest.config.ts` z `test.projects`; `web` w `jsdom`, reszta w `node`; pokrycie `v8`. Testy aplikacji w `apps/<app>/tests` (lustro `src/`), pomocnicze w `tests/support`; testy bazy na Postgresie z `@testcontainers/postgresql`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| Web               | Domeny w `domains/<domena>/` ze stanem bez Reacta w `model/`; wspólne `core/` (czysty TS), `hooks/`, `board/`, `ui/` (ADR-0012). Widoki przełączane przez React Router (`createBrowserRouter`) po ścieżce (`/ranking`, `/pokoj/<kod>`); gra i 1v1 zostają zamontowane w tle, trasa wskazuje tylko widok. Serwer zwraca `index.html` dla ścieżek bez rozszerzenia (poza `/api`), a stare linki z hashem (`#/pokoj/<kod>`) web zamienia na ścieżki. CSS Modules w SCSS, tokeny kolorów w `ui/global.scss`. Komponent ze stylami to folder `Nazwa/` z `Nazwa.tsx` i `Nazwa.module.scss`, bez `index.ts`; komponent bez styli to sam `Nazwa.tsx`. Wspólny arkusz jest tylko jeden: `board/board.module.scss` (pilnuje `tests/conventions.test.ts`) |
| Nazwa             | Gracz widzi **Blockfall** (tytuł, nagłówek, README); wewnętrzne nazwy (repo, `@tetris/*`, chart, namespace'y) zostają                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| CI                | Job `quality`: checkout → setup-node (`.nvmrc`, cache yarn) → `install --immutable` → lint → format:check → typecheck → test:coverage. Ruleset `main-quality-gates`: wymagany `quality`, zmiany tylko przez PR, zakaz force-push                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |

Poza zakresem: Turborepo, hooki `commit-msg` i `pre-push`, pakiety workspace na warstwy (ADR-0011).
